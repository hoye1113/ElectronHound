# Pi Migration Design: LangGraph → Pure TypeScript Agent Loop

**Date:** 2026-05-28
**Status:** Draft — pending review
**Branch:** master
**Reference:** origin/release/v0.3

## Context

ElectronHound's `packages/agent-core` currently uses LangGraph (`@langchain/langgraph`) for agent orchestration and Vercel AI SDK (`ai`, `@ai-sdk/*`) for LLM calls. These frameworks are heavyweight dependencies for a narrow feature set — the project only uses basic graph topology, state annotations, SQLite checkpointing, and OpenAI-compatible LLM calls.

The `release/v0.3` branch has already completed a Pi migration that replaces both frameworks with pure TypeScript, but has 8 known defects and was never merged into `master`.

This spec defines a 5-wave migration strategy to bring the Pi architecture into `master` safely.

## Goals

1. Remove LangGraph dependency (`@langchain/langgraph`, `@langchain/langgraph-checkpoint-sqlite`, `@langchain/core`)
2. Remove Vercel AI SDK dependency (`ai`, `@ai-sdk/openai`, `@ai-sdk/anthropic`, `@ai-sdk/google`, `ai-sdk-ollama`)
3. Adopt pure TypeScript Agent Loop from release/v0.3 as the new orchestration layer
4. Adopt native-fetch LLMProvider as the new LLM layer
5. Integrate compaction module into the new agent loop
6. Maintain backward compatibility with server orchestration (worker-entry.ts, workerManager.ts)
7. Each wave is independently PR-able and CI-verifiable

## Non-Goals

- Adding new features beyond what release/v0.3 already implements
- Refactoring the server or dashboard architecture
- Changing the MCP client or sub-agent systems (these have no LangGraph dependency)

## Current Architecture (master)

### LangGraph Dependency Surface

**7 source files** directly import LangGraph:

| File | LangGraph Feature |
|------|-------------------|
| `packages/agent-core/src/state.ts` | `Annotation.Root()` — 14-field typed state |
| `packages/agent-core/src/graph.ts` | `StateGraph` — 6-node test graph with conditional edges |
| `packages/agent-core/src/report-graph/state.ts` | `Annotation.Root()` — 7-field report state |
| `packages/agent-core/src/report-graph/graph.ts` | `StateGraph` — 5-node report sub-graph (fan-out/fan-in) |
| `packages/agent-core/src/checkpoint.ts` | `SqliteSaver` — SQLite checkpoint persistence |
| `packages/agent-core/src/runner.ts` | `graph.compile()` + `compiled.invoke()` |
| `packages/agent-core/src/index.ts` | Re-exports `createCheckpointer`, `createTestGraph` |

**6 node files** depend on LangGraph types indirectly:
- `nodes/observe.ts`, `nodes/plan.ts`, `nodes/execute.ts`, `nodes/verify.ts`, `nodes/abort.ts`, `nodes/report.ts`
- All accept `typeof TestState.State` (generated by `Annotation.Root()`)

**NOT affected** (no LangGraph dependency):
- `llm.ts`, `llm-types.ts`, `provider-factory.ts` — Vercel AI SDK only
- `sub-agents/` — plain classes
- `mcp/client.ts` — MCP SDK only
- `guards.ts` — Zod only
- `config-manager.ts` — Node.js fs/crypto
- `apps/server/` — never imports LangGraph

### LLM Layer (Vercel AI SDK)

- `llm.ts`: Uses `createOpenAI` from `@ai-sdk/openai` + `generateObject` from `ai`
- `provider-factory.ts`: Unified OpenAI-compatible interface via `createOpenAI`
- `llm-types.ts`: `LLMProviderConfig` with type `'openai-compatible'` only
- Built-in templates: OpenAI, DeepSeek, Qwen, Groq

## Target Architecture

### Agent Loop (replaces StateGraph)

A `while` loop implementing observe→plan→execute→verify→report cycle:

```
while (stepCount < maxSteps) {
  observation = observe(state)
  if (stuckDetector.isStuck()) → abort
  plan = planPhase(observation)
  result = execute(plan)
  verdict = verify(result)
  if (verdict === 'pass') → report → done
  if (verdict === 'fail') → retry
  if (verdict === 'stuck') → abort
}
```

- State is a plain mutable `AgentLoopState` object (no Annotation/reducer)
- Routing is `if/else` on verdict values (no conditional-edge graph)
- Returns `AgentRunResult` with verdict, report, sessionId

### LLMProvider (replaces Vercel AI SDK)

```typescript
interface LLMProvider {
  generateObject<T>(opts: GenerateObjectOpts): Promise<{ object: T }>
  generateText(opts: GenerateTextOpts): Promise<{ text: string }>
}
```

- Schema uses lightweight `{ parse(v: unknown): T }` interface (no Zod at provider level)
- `createOpenAIProvider()` uses native `fetch()` against `/chat/completions`
- Supports any OpenAI-compatible API via configurable `baseURL`

### Session/Persistence (replaces LangGraph checkpoint)

- `session/persistence.ts` — SQLite schema (sessions, entries, compactions) via `better-sqlite3`
- `session/sessionManager.ts` — High-level CRUD (createSession, addEntry, getSession, compactSession)
- Every agent loop step recorded via `session.addEntry()`

### Tools (new)

- `tools/types.ts` — Tool interface, ToolResult, ToolRegistry
- `tools/registry.ts` — Default registry with Zod validation
- `tools/cdp.ts` — CDP tools (7 browser + 5 electron)

### Compaction (integrated into agent loop)

- Token counting, cut-point detection, summary generation
- Merged from release/v0.3's `loop/agentLoop.ts` into the new `runtime/agentLoop.ts`

## Migration Plan: Five Waves

### Wave 0 — Low-Risk Cherry-Picks

**Goal:** Bring valuable non-architectural fixes from release/v0.3 into master.

**Cherry-pick targets:**

| Commit | Description | Files |
|--------|-------------|-------|
| `753ab9a` | i18n colon fixes (en.json, zh.json, page components) | 9 |
| `8b76aae` | Dashboard test fixes (mockTask priority, t scope in TreeNode) | 3 |
| `571f9bc` (partial) | FewShotPage, AuditReportView, LanguageSwitcher, i18n tests | ~6 |

**Note:** `571f9bc` is a large commit (+1487 lines). Cherry-pick dashboard components selectively, skip server/agent-core changes. Specific files to extract:
- `apps/dashboard/src/pages/FewShotPage.tsx`
- `apps/dashboard/src/components/AuditReportView.tsx`
- `apps/dashboard/src/components/LanguageSwitcher.tsx`
- `apps/dashboard/src/__tests__/i18n.test.tsx`
- Related i18n key additions in `en.json` / `zh.json`

**Verification:** `pnpm build` passes, CI green.

### Wave 1 — LLM Layer Migration

**Goal:** Replace Vercel AI SDK with native-fetch LLMProvider.

**Delete:**
- Dependencies: `@ai-sdk/openai`, `@ai-sdk/anthropic`, `@ai-sdk/google`, `ai-sdk-ollama`, `ai`
- Source: `packages/agent-core/src/llm.ts` (old Vercel AI SDK calls)
- Source: `packages/agent-core/src/provider-factory.ts` (old provider factory)

**Introduce (from release/v0.3):**
- `packages/agent-core/src/llm/types.ts` — LLMProvider interface
- `packages/agent-core/src/llm/openai-provider.ts` — native fetch implementation
- `packages/agent-core/src/llm/adapter.ts` — bridge for old node code (transitional)

**Fixes needed (release/v0.3 defects):**
- `model` param in adapter should not be a "dummy" — document clearly or remove

**Verification:** Existing LLM-related tests pass. `pnpm typecheck` passes.

### Wave 2 — Session/Persistence Migration

**Goal:** Replace LangGraph checkpoint with custom SQLite persistence.

**Delete:**
- `packages/agent-core/src/checkpoint.ts` (LangGraph SqliteSaver)

**Introduce (from release/v0.3):**
- `packages/agent-core/src/session/persistence.ts` — SQLite schema + prepared statements
- `packages/agent-core/src/session/sessionManager.ts` — high-level CRUD
- `packages/agent-core/src/session/types.ts` — type definitions

**Verification:** Session CRUD tests pass. SQLite database created correctly.

### Wave 3 — Agent Loop + Tools + Compaction (Core)

**Goal:** Replace LangGraph StateGraph with pure TypeScript agent loop. This is the largest and riskiest wave.

**Delete:**
- `packages/agent-core/src/graph.ts` (LangGraph StateGraph)
- `packages/agent-core/src/state.ts` (Annotation.Root state)
- `packages/agent-core/src/nodes/` directory (6 old node files)
- `packages/agent-core/src/report-graph/` directory

**Introduce (from release/v0.3):**
- `packages/agent-core/src/runtime/agentLoop.ts` — core while loop (with compaction integrated)
- `packages/agent-core/src/runtime/stuckDetection.ts` — stuck detector
- `packages/agent-core/src/runtime/types.ts` — runtime types
- `packages/agent-core/src/tools/types.ts` — Tool interface
- `packages/agent-core/src/tools/registry.ts` — Tool registry
- `packages/agent-core/src/tools/cdp.ts` — CDP tools

**Dependencies to add:** `zod` (required by `tools/registry.ts` and `tools/cdp.ts` for schema validation).

**Known defects to fix during migration:**

1. **Tool execution stub** — `runtime/agentLoop.ts` returns stub when no MCP client. Must wire real MCP client or provide a fallback.
2. **Empty report goal** — `Report` object uses `goal: ''`. Must carry original task prompt.
3. **Stubbed runner fields** — `RunTestResult` has hardcoded empty values. Must map AgentLoop result fully.
4. **Dual agent loop** — Merge `loop/agentLoop.ts` (has compaction) into `runtime/agentLoop.ts` (has new LLMProvider). Delete `loop/` directory.
5. **CDPClient skeleton** — `waitForConnection()` is no-op. Either implement or mark as explicit TODO with issue reference.

**Verification:** End-to-end agent execution passes. Server can spawn worker and complete a task.

### Wave 4 — Cleanup

**Goal:** Remove all LangGraph traces and update documentation.

**Actions:**
- Remove from `package.json`: `@langchain/langgraph`, `@langchain/langgraph-checkpoint-sqlite`, `@langchain/core`
- Update `packages/agent-core/src/index.ts`: remove old exports (`createCheckpointer`, `createTestGraph`)
- Update `packages/agent-core/package.json`: remove description/keywords referencing LangGraph
- Update `apps/server/src/services/workerManager.ts`: remove LangGraph checkpoint comments
- Update `packages/agent-core/src/worker-entry.ts`: remove `--thread-id` arg if no longer needed
- Update README and docs
- Run `pnpm install` to clean lockfile

**Verification:** Full CI pass. `pnpm typecheck && pnpm test && pnpm build` all green.

## Risk Assessment

| Wave | Risk | Mitigation |
|------|------|------------|
| 0 | Low | Cherry-pick with conflict resolution |
| 1 | Medium | LLM adapter bridges old node code during transition |
| 2 | Medium | Session module is self-contained, testable in isolation |
| 3 | High | Largest change; fix known defects; test end-to-end |
| 4 | Low | Dependency removal, no logic changes |

## Success Criteria

1. Zero LangGraph imports in the codebase
2. Zero Vercel AI SDK imports in the codebase
3. `pnpm typecheck` passes across all workspace packages
4. `pnpm test` passes across all workspace packages
5. `pnpm build` passes across all workspace packages
6. End-to-end agent execution works (server → worker → agent loop → report)
7. All release/v0.3 known defects resolved or explicitly tracked as TODOs
