# [B-001] 测试性能优化

## 问题

当前测试时间 ~81s，目标 <30s。需要分析慢测试并优化。

## 根因

1. 测试文件数量增加（100 个文件）
2. 每个测试文件独立启动 vitest 环境
3. 部分测试使用真实 API 调用
4. 测试 setup/teardown 重复执行

## 修复方案

### 优化策略

1. **并行化测试执行**
   - 使用 `vitest --pool=threads` 并行执行
   - 配置 `maxThreads` 优化 CPU 使用

2. **优化测试 setup**
   - 共享 mock 数据
   - 减少重复的 mock 初始化
   - 使用 `beforeAll` 替代 `beforeEach`（安全时）

3. **减少不必要的渲染**
   - 使用 `screen.queryBy*` 替代 `screen.getBy*`（非断言时）
   - 避免重复渲染相同组件

4. **优化 mock 策略**
   - 使用 `vi.hoisted` 提升 mock 定义
   - 减少 mock 层级

### 实施步骤

1. 分析慢测试文件（>1s）
2. 优化 vitest 配置
3. 重构慢测试文件
4. 验证优化效果

### 验收标准

- [ ] 测试时间 <30s
- [ ] 所有测试仍然通过
- [ ] 覆盖率不下降

## 回归风险

**低** — 优化测试性能，不影响源代码。
