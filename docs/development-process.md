# 开发流程规范

## 概述

本文档定义了 ElectronHound 项目的开发流程规范，确保代码质量和一致性。

## 阶段流程

每个开发阶段必须遵循以下流程：

```
任务执行 → Code Review → 修复问题 → 再次 Code Review → ... → 提交 Commit → 进入下一阶段
```

### 详细步骤

1. **任务执行**
   - 启动 sub agent 执行任务
   - 监控进度和质量
   - 收集执行结果

2. **Code Review**
   - 执行 `/code-review` 技能
   - 检查代码质量
   - 识别问题和改进点

3. **问题修复**
   - 修复所有发现的问题
   - 重新运行测试
   - 验证修复效果

4. **再次 Code Review**
   - 再次执行 `/code-review`
   - 确认所有问题已解决
   - 验证质量达标

5. **提交 Commit**
   - 创建语义化提交信息
   - 提交所有变更
   - 推送到远程仓库

6. **进入下一阶段**
   - 验证当前阶段完成
   - 准备下一阶段任务
   - 继续执行

## 质量门禁

每个阶段必须满足以下条件才能进入下一阶段：

- [ ] Code Review 通过
- [ ] 所有测试通过
- [ ] 无严重 bug
- [ ] 代码质量达标
- [ ] 文档更新完整

## Code Review 规范

### 审查深度

- **standard**：标准代码审查（默认）
- **deep**：深度审查（变更超过 500 行或涉及关键功能）

### 审查重点

- **general**：标准代码审查（默认）
- **architecture**：架构、职责边界、SOLID、扩展性
- **security**：安全、权限、可靠性、并发风险
- **cleanup**：冗余逻辑、死代码、删除计划

### 问题标签

- **[Required]**：必须修改，阻断合并
- **[Optional]**：建议改进，不阻断合并
- **[Question]**：需要作者澄清
- **[FYI]**：信息同步或后续建议

## 提交规范

### 提交信息格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 类型（type）

- **feat**：新功能
- **fix**：修复 bug
- **docs**：文档更新
- **style**：代码格式调整
- **refactor**：重构
- **perf**：性能优化
- **test**：测试相关
- **chore**：构建/工具链更新

### 范围（scope）

- **infra**：基础设施
- **server**：服务器端
- **dashboard**：仪表板
- **agent-core**：核心代理
- **shared-types**：共享类型

### 示例

```
feat(infra): 完善基础设施和代码质量

- 创建 LICENSE、SECURITY.md、CODE_OF_CONDUCT.md
- 更新 .gitignore 覆盖全面
- 移除所有 as any 类型断言
- 完善错误处理和输入验证
- 提升测试覆盖率至目标水平
```

## 阶段定义

### P0 阶段：基础设施和代码质量

**目标**：建立项目基础，提高代码质量

**任务清单**：
1. 创建规范文件（LICENSE、SECURITY.md、CODE_OF_CONDUCT.md）
2. 更新 .gitignore
3. 代码质量改进（移除 `as any`、完善错误处理、添加输入验证）
4. 测试覆盖率提升

**验收标准**：
- [ ] 所有规范文件格式正确
- [ ] TypeScript 严格模式通过
- [ ] 无 `as any` 类型断言
- [ ] 错误处理完整
- [ ] 输入验证覆盖所有 API 端点
- [ ] 测试覆盖率达标

### P1 阶段：文档和开发者体验

**目标**：完善文档，优化开发者体验

**任务清单**：
1. 文档完善（用户手册、API 文档、架构说明、故障排除指南）
2. 开发者体验优化（错误提示、日志格式、配置向导、进度反馈）

**验收标准**：
- [ ] 文档完整，覆盖所有主要功能
- [ ] 示例代码可运行
- [ ] 架构图清晰易懂
- [ ] 错误提示清晰易懂
- [ ] 日志格式统一
- [ ] 配置向导可用
- [ ] 进度反馈及时

### P2 阶段：功能完善和性能优化

**目标**：完善功能，优化性能

**任务清单**：
1. 功能完善（批量测试、报告格式定制、测试模板、结果导出）
2. 性能优化（启动时间、内存使用、并发性能、资源清理）
3. 稳定性改进（错误恢复、超时处理、进程管理、状态一致性）

**验收标准**：
- [ ] 新功能正常工作
- [ ] 性能指标达标
- [ ] 稳定性测试通过
- [ ] 无资源泄漏
- [ ] 错误恢复机制有效
- [ ] 超时处理合理

## 工具和脚本

### Code Review

```bash
# 执行标准审查
/code-review

# 执行深度审查
/code-review --depth deep

# 执行安全审查
/code-review --focus security
```

### 测试

```bash
# 运行所有测试
pnpm test

# 运行特定模块测试
pnpm --filter @eata/server test

# 运行测试并生成覆盖率报告
pnpm test --coverage
```

### 类型检查

```bash
# 检查所有模块
pnpm typecheck

# 检查特定模块
pnpm --filter @eata/server typecheck
```

### 代码格式化

```bash
# 格式化所有代码
pnpm format

# 检查格式
pnpm lint
```

## 最佳实践

1. **小步提交**：每次提交只做一件事
2. **语义化提交**：使用规范的提交信息
3. **测试驱动**：先写测试，再写代码
4. **代码审查**：所有代码必须经过审查
5. **文档同步**：代码变更必须同步更新文档
6. **持续集成**：所有提交必须通过 CI 检查

## 常见问题

### Q: Code Review 发现问题怎么办？

A: 修复所有问题，然后再次执行 Code Review，直到所有问题解决。

### Q: 如何确定审查深度？

A: 默认使用 standard 深度。如果变更超过 500 行或涉及关键功能，使用 deep 深度。

### Q: 提交信息格式是什么？

A: 使用 `<type>(<scope>): <subject>` 格式，详见提交规范。

### Q: 如何处理紧急修复？

A: 紧急修复也必须经过 Code Review，但可以简化流程。
